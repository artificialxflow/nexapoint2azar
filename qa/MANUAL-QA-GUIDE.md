# راهنمای تست دستی جامع نکساپوینت (دو مرورگر)

**نسخه:** هم‌تراز با منوی `Sidebar.tsx` و مسیرهای `view-map.tsx`  
**محیط پیشنهادی:** production (`https://nexapoint.ir`) یا staging محلی  
**مرورگر ۱:** مدیر کل سیستم / مالک کسب‌وکار  
**مرورگر ۲:** کارمند با preset **تمرکز فروش** (`sales_only`) و عضویت همان کسب‌وکار  
**نحوه تیک:** `- [ ]` را به `- [x]` تبدیل کنید.

## ۰. پیش‌نیاز و نکات کلی

- [ ] دو مرورگر یا پروفایل جدا (یکی عادی + یکی ناشناس)؛ کوکی/نشست مشترک نداشته باشند.
- [ ] پس از ورود، هر دو از مسیر **`/businesses`** همان **کسب‌وکار تست** را انتخاب کنند.
- [ ] در هدر داشبورد، نام کسب‌وکار و وضعیت ورود درست باشد.
- [ ] جهت UI: RTL فارسی.
- [ ] برای هر باگ: اسکرین‌شات، URL کامل، نقش، زمان.

**تفاوت مهم در معماری دسترسی (کد واقعی):**

| لایه | منبع | اثر |
|------|------|-----|
| نقش سیستمی | `systemRole` + `accessLevelPreset` | تنظیمات، دعوت، CRM/فروش/مالی در سطح ERP |

## ۱. آماده‌سازی و ساخت دو کاربر

### ۱.۱ محیط و کسب‌وکار

- [ ] **گزینه A — تمیز:** مرورگر ۱ → ورود مدیر → `/businesses` → **راه‌اندازی کسب‌وکار جدید** (`/businesses/new`) → نام (مثلاً `QA-Manual-تاریخ`) → ورود به داشبورد.
- [ ] **گزینه B — موجود:** `/businesses` → انتخاب کسب‌وکار ثابت (مثلاً رونام) → **ورود**.
- [ ] **تنظیمات کسب‌وکار:** سایدبار **سیستم → تنظیمات** → `/dashboard/settings?tab=business` → ذخیره نام حقوقی/تجاری.
- [ ] (اختیاری) **سال مالی** در همان صفحه تکمیل شود.

### ۱.۲ کاربر ۱ — مدیر کل (مرورگر ۱)

- [ ] کاربر فعلی `super_admin` یا مدیر با **دسترسی کامل** (`settings:all` / preset `full`).
- [ ] `تنظیمات → کاربران و دسترسی` (`/dashboard/settings?tab=access`) بدون پیام «دسترسی به مدیریت کاربران ندارید» باز شود.

### ۱.۳ کاربر ۲ — کارمند فروشنده (مرورگر ۲)

**ساخت در مرورگر ۱:**

- [ ] `تنظیمات → کاربران و دسترسی → کاربران و نقش‌ها`
- [ ] دکمه **افزودن کاربر**:
  - نام نمایشی (مثلاً «کارمند فروش QA»)
  - شماره موبایل (ورود با پیامک)
  - نقش سیستمی مناسب (مثلاً فروش)
  - تحویل: **مستقیم** (رمز دستی) یا **دعوت**
- [ ] **انتظار:** تا **فعال‌سازی** توسط مدیر، کاربر نمی‌تواند وارد شود.
- [ ] در لیست کاربران: **فعال‌سازی** (یا تأیید در **درخواست‌های ورود در انتظار تأیید**).
- [ ] زیربخش **سطح دسترسی** → انتخاب کاربر دوم → preset **تمرکز فروش** → **ذخیره سطح دسترسی**  
  *(مجوزها: مشاهده/ثبت فروش، CRM، گزارشات — بدون مدیریت کاربران)*

**عضویت کسب‌وکار:**

- [ ] API provision کاربر جدید را به **همان `businessId` مدیر** با نقش `member` اضافه می‌کند؛ هر دو باید همان کسب‌وکار را در `/businesses` ببینند.
- [ ] مدیر: `/dashboard/hr?tab=org` یا لینک چارت از تنظیمات کسب‌وکار → نام کارمند در **تیم** (team-directory) دیده شود.

**ورود کارمند (مرورگر ۲):**

- [ ] خروج از مرورگر ۲ → ورود با موبایل/رمز کارمند → `/businesses` → انتخاب **همان کسب‌وکار**.

### ۱.۴ چک اولیه دسترسی کارمند

- [ ] مرورگر ۲ → `/dashboard/settings?tab=access` → انتظار: عدم دسترسی به مدیریت کاربران یا پیام محدودیت.
- [ ] مرورگر ۲ → `/dashboard/hr` → تب **ساعت و حقوق** / سایدبار قوانین وام → کمتر یا بدون ابزار مدیریتی نسبت به owner/admin کسب‌وکار.

| گام | مرورگر ۱ (مدیر) | مرورگر ۲ (کارمند) | انتظار |
